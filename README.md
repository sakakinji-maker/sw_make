# 소상공인용 AI 마케팅·고객응대 통합 지원 시스템

> 융합SW모델설계 PBL 과제 1 · 2026학년도 2학기 · 팀 **신창섭**

소상공인 점주가 **예약·문의·홍보** 업무를 한 화면에서 처리하고, 생성형 AI로 답변과 홍보 문구 작성 부담을 줄이는 웹 시스템입니다. AI는 초안만 만들고 최종 확정은 항상 점주가 합니다.

- 기획서 및 요구사항 정의서: [Claude 문서 링크](https://claude.ai/artifact/V2xe6GyYuFoP2MaS8sb3xY) (`docs/` 참고)
- 수행 기간: 10주차(10/27) ~ 14주차(11/24), **15주차(12/1) 최종 발표**

| 이름 | 역할 | 담당 기능 | 디자인 패턴 | 담당 문서·업무 |

| 정회성 | 개발·검증 | F-03 문의 접수·AI 답변 초안 | Adapter | 코딩 규칙·CLAUDE.md, GitHub 관리, 테스트 케이스, AI 활용 로그, AI 검증 보고서 |
| 전지호 | 설계 | F-04 채널별 AI 홍보 문구, F-05 대시보드 | Strategy | 아키텍처(4+1), 클래스 다이어그램·SOLID, ERD |

## 실행 방법

```bash
# 1. 가상환경과 패키지
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. 환경 변수 (처음 한 번)
cp .env.example .env               # Windows: copy .env.example .env

# 3. 샘플 데이터 넣기
python -m app.db.seed

# 4. 서버 실행
uvicorn app.main:app --reload
```

- 고객 화면: http://127.0.0.1:8000/
- 점주 화면: http://127.0.0.1:8000/owner
- API 문서: http://127.0.0.1:8000/docs

```bash
pytest           # 테스트
ruff check .     # 린트
ruff format .    # 포맷
```

`.env`의 `AI_PROVIDER=mock`이면 실제 AI를 호출하지 않습니다. 실제 API는 시연·검증 때만 `external`로 바꿉니다.

## 폴더 구조

```
app/
  presentation/            # 프레젠테이션 계층
    routers/               #   owner.py (점주), customer.py (고객)
    templates/owner/       #   점주 화면
    templates/customer/    #   고객 화면
  services/                # 비즈니스 로직 계층
    reservation/           #   예약 서비스 + 상태 클래스 (State)        ← 한재형
    inquiry/               #   문의 서비스 + FactChecker (DB 대조)      ← 정회성
    marketing/             #   홍보 서비스 + 채널 전략 (Strategy)       ← 전지호
  adapters/ai/             # AIClient 인터페이스, Mock, 실제 API (Adapter) ← 정회성
  repositories/            # DB 조회·저장
  models/                  # Store, MenuItem, FAQ, Customer, Reservation ...
  db/                      # DB 연결, 가상 데이터 적재 스크립트
tests/                     # 기능별 정상·예외 테스트
docs/                      # 기획서, 설계서, AI 활용 로그, 검증 보고서
CLAUDE.md                  # 팀 코딩 규칙
```

## 디자인 패턴

| 패턴 | 위치 | 무엇이 자주 바뀌는가 |
| --- | --- | --- |
| State | `app/services/reservation/states.py` | 예약 정책(취소 가능 시점, 새 상태 추가) |
| Strategy | `app/services/marketing/strategies.py` | 홍보 채널 추가, 채널별 규칙 변경 |
| Adapter | `app/adapters/ai/` | AI 제공사·모델 변경, 테스트용 Mock 전환 |

## 협업 규칙

- 브랜치: `main`(제출용) ← `develop`(통합) ← `feature/F-03-ai-draft` 처럼 기능 ID로 만든다.
- `main`, `develop`에 직접 push하지 않고 Pull Request로 병합한다. 리뷰어 1명 이상 승인.
- 커밋 메시지: `feat: F-02 예약 취소 기능`, `fix:`, `test:`, `docs:`, `refactor:` 접두어 사용.
- PR 올리기 전 `pytest`와 `ruff check .` 통과 확인.
- API 키는 `.env`에만 넣고 절대 커밋하지 않는다.
